## 1. Call Stack और Execution Mechanism

जब कोई फंक्शन खुद को कॉल करता है, तो ऑपरेटिंग सिस्टम memory के **Call Stack** एरिया का उपयोग करता है।

* **Activation Record (Stack Frame):** हर फंक्शन कॉल के लिए स्टैक पर एक नया Frame बनता है, जिसमें उस कॉल के local variables, parameters, और return address स्टोर होते हैं।
* **Winding vs. Unwinding Phase:**
* **Winding Phase:** फंक्शन तब तक नए frames स्टैक पर पुश करता रहता है जब तक वह Base Case तक न पहुँच जाए।
* **Unwinding Phase:** Base Case hit होने के बाद, वैल्यूज़ वापस लौटती (return होती) हैं और स्टैक frames एक-एक करके Pop (हटने) होने लगते हैं।



> **Stack Overflow Alert:** अगर आपका Base Case गलत है या ट्रिगर नहीं हो पाता, तो Stack Memory पूरी भर जाती है, जिससे `StackOverflowError` मिलता है।

## 2. Direct vs. Indirect Recursion

* **Direct Recursion:** जब फंक्शन $A$ सीधे खुद $A$ को कॉल करे।

$$\text{Function } A \longrightarrow \text{Function } A$$


* **Indirect Recursion:** जब फंक्शन $A$ फंक्शन $B$ को कॉल करे, और $B$ वापस $A$ को कॉल करे (एक साइकिल बन जाए)।

$$\text{Function } A \longrightarrow \text{Function } B \longrightarrow \text{Function } A$$

## 3. Tail Recursion vs. Non-Tail Recursion

यह अंतर समझ पाना एक Intermediate Coder के लिए बेहद ज़रूरी है, क्योंकि यह कम्पाअइलर ऑप्टिमाइजेशन (Compiler Optimization) से जुड़ा है।

### Tail Recursion

जब रिकर्सिव कॉल फंक्शन का **अंतिम स्टेटमेंट** होता है और उसके बाद कोई ऑपरेशन्स (जैसे जोड़ना या गुणा करना) बाकी नहीं रहता।

```python
def tail_fact(n, accumulator=1):
    if n == 1:
        return accumulator
    return tail_fact(n - 1, n * accumulator)  # अंतिम काम केवल रिकर्सिव कॉल है

```

### Non-Tail Recursion

जब रिकर्सिव कॉल से वापस लौटने के बाद भी कोई ऑपरेशन बचा रहता है।

```python
def fact(n):
    if n == 1:
        return 1
    return n * fact(n - 1)  # रिकर्शन का रिजल्ट आने के बाद 'n' से मल्टीप्लाई होना बाकी है

```

* **Tail Call Optimization (TCO):** आधुनिक कम्पाइलर्स Tail-recursive कोड को पहचानकर उसे एक लूप (loop) की तरह ऑप्टिमाइज़ कर देते हैं, जिससे स्टैक ओवरफ्लो की समस्या खत्म हो जाती है और अतिरिक्त memory खर्च नहीं होती ($O(1)$ auxiliary space)।

## 4. Time and Space Complexity Analysis

रिकर्सिव फंक्शंस की कॉम्प्लेक्सिटी निकालने के लिए **Recurrence Relations** का उपयोग किया जाता है।

### Binary Search (Divide and Conquer)

* **Recurrence Relation:** $T(n) = T(n/2) + O(1)$
* **Time Complexity:** $O(\log n)$
* **Auxiliary Space Complexity:** $O(\log n)$ (call stack की गहराई के कारण)

### Fibonacci Series (Naive Recursion)

* **Recurrence Relation:** $T(n) = T(n-1) + T(n-2) + O(1)$
* **Time Complexity:** $O(2^n)$ — यह Exponential टाइम लेता है क्योंकि इसमें समान सब-प्रॉब्लम्स बार-बार कैलकुलेट होती हैं।
* **Space Complexity:** $O(n)$ (स्टैक की अधिकतम गहराई के बराबर)

## 5. Tree Recursion और Subproblem Overlapping

जब एक फंक्शन एक ही execution में खुद को **दो या दो से अधिक बार** कॉल करता है, तो उसे Tree Recursion कहते हैं।

```
                  fib(4)
               /          \
           fib(3)        fib(2)
          /      \       /     \
      fib(2)   fib(1) fib(1)  fib(0)
     /      \
  fib(1)   fib(0)

```

ध्यान से देखें, `fib(2)` को बार-बार कैलकुलेट किया जा रहा है। इस ओवरलैपिंग को रोकने के लिए ही आगे **Dynamic Programming (Memoization / Tabulation)** की ज़रूरत पड़ती है।
