नमस्ते! आज हम Array के बारे में बेहद गहराई से समझेंगे। चूंकि आपका लेवल Expert है (यानी आप प्रोग्रामिंग की बुनियादी बातें, मेमोरी मैनेजमेंट और डेटा स्ट्रक्चर्स से पहले से वाकिफ हैं), हम सीधे इसके Internal Working (आंतरिक कार्यप्रणाली), Memory Layout, और इसके परफॉर्मेंस ट्रेड-offs पर बात करेंगे।

1. Memory Representation और Contiguous Allocation

कंप्यूटर की मेमोरी में Array का मतलब होता है—Contiguous Memory Locations (यानी लगातार मिलने वाले मेमोरी ब्लॉक्स)।

जब आप किसी Array को डिक्लेअर करते हैं (मान लीजिए int arr[5]), तो ऑपरेटिंग सिस्टम रैम (RAM) में एक ऐसा ब्लॉक ढूंढता है जहाँ 5 इंटीजर्स लगातार आ सकें।

मान लीजिए पहला एलिमेंट arr[0] मेमोरी एड्रेस 1000 पर स्टोर है, और एक इंटीजर 4 bytes लेता है:

arr[0] → 1000

arr[1] → 1004

arr[2] → 1008

arr[3] → 1012

arr[4] → 1016

इस कंटीन्यूअस अरेंजमेंट की वजह से ही CPU किसी भी एलिमेंट को O(1) समय में ढूंढ सकता है। इसका फॉर्मूला सीधा सा होता है:

Address = Base Address + (Index × Size of Data Type)

2. Time Complexity Analysis (Big-O)

| ऑपरेशन (Operation) | Static Array (Fixed Size) | Dynamic Array (जैसे C++ का std::vector या Python की list) |
|---|---|---|
| Access (रैंडम एक्सेस) | O(1) | O(1) |
| Search (अनसॉर्टेड) | O(N) | O(N) |
| Insertion (अंत में / End) | O(1) (अगर क्षमता बची हो) | Amortized O(1) (डबलिंग स्ट्रेटजी के कारण) |
| Insertion (बीच में / Middle) | O(N) (एलिमेंट्स को शिफ्ट करना पड़ता है) | O(N) |
| Deletion (बीच से / Middle) | O(N) | O(N) |

3. Dynamic Arrays कैसे काम करते हैं? (Under the Hood)

जब आप C++ में std::vector या Java में ArrayList बनाते हैं, तो वे अंदर से Static Array ही इस्तेमाल करते हैं। लेकिन फिर वे साइज कैसे बढ़ाते हैं?

जब अरे पूरी तरह भर जाता है (Capacity = Size), तो यह दोगुने साइज (2 × N) का एक नया और बड़ा मेमोरी ब्लॉक एलोकेट करता है।

पुराने अरे के सारे एलिमेंट्स को नए मेमोरी ब्लॉक में कॉपी (Copy/Move) किया जाता है।

पुराने वाले ब्लॉक को फ्री (free/delete) कर दिया जाता है।

यही वजह है कि हर बार रीसाइज़िंग महंगी होती है, लेकिन चूंकि यह बहुत कम बार होती है, इसलिए इसका Amortized Time Complexity इंसर्ट करने के लिए O(1) ही माना जाता है।
