1. आसान भाषा में समझो
Relational database में primary key (टेबल में हर row को अलग पहचानने वाली अनोखी पहचान) एक या ज़्यादा columns का मेल होती है, जो हर record (एक पंक्ति या जानकारी का सेट) को uniquely identify करती है। Primary key में कभी भी NULL (खाली या अज्ञात मान) नहीं हो सकता और इसकी values हमेशा unique होती हैं।

SQL
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    email VARCHAR(100) UNIQUE,
    name VARCHAR(50)
);
अगर कोई नया row जोड़ते समय existing student_id डाला जाए, तो database constraint violation error (नियम टूटने की गड़बड़ी) देता है। एक table में केवल एक ही primary key हो सकती है, लेकिन वह multiple columns से मिलकर बन सकती है जिसे composite key (एक से ज़्यादा कॉलम वाली चाबी) कहते हैं।

2. रोज़मर्रा की ज़िंदगी से मिसाल
कॉलेज में हर छात्र का अपना unique roll number होता है। दो छात्रों का नाम एक हो सकता है, लेकिन roll number कभी एक नहीं होता। यह मिसाल कहाँ टूटती है: इंसान बिना roll number के भी छात्र रह सकता है, पर database की table का record बिना valid primary key के identify होना मुश्किल हो जाता है।

3. ज़रूरी शब्द (Key Terms)
Primary key – हर row को अनोखा बताने वाला कॉलम

Unique – जिसका मान दोहराया न जा सके

NULL – खाली या बिना मान वाली जगह

Composite key – एक से ज़्यादा columns वाली primary key

4. आम गलतफ़हमी
गलतफ़हमी: जिस कॉलम में UNIQUE लिखा हो, वह automatically primary key बन जाता है। सही बात: UNIQUE कॉलम में NULL values आ सकती हैं, जबकि primary key में कभी भी NULL नहीं आ सकता।
